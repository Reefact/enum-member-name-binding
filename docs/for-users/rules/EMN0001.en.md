# EMN0001 — Two enum members declare the same public name

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0001.fr.md)

| | |
|---|---|
| **Severity** | Error |
| **Category** | ApiContract |
| **Also enforced** | at start-up, by `EnumContractException` |

## Cause

Two members of the same enum declare the same value in `[JsonStringEnumMemberName]`.

<!-- emn:allow=EMN0001 -->
```csharp
public enum Status
{
    [JsonStringEnumMemberName("same")] First,   // EMN0001
    [JsonStringEnumMemberName("same")] Second
}
```

## Why it matters

A public name is how a caller designates one member of your enum. When two members answer to the
same name, the value is not resolvable: the binder picks the first declaration, and the second
member becomes unreachable — silently, and in declaration order, so reordering the enum changes the
meaning of an API contract.

`System.Text.Json` rejects the same shape.

## How to fix

Give each member a distinct public name.

```csharp
public enum Status
{
    [JsonStringEnumMemberName("first")]  First,
    [JsonStringEnumMemberName("second")] Second
}
```

Two members may share the same *numeric* value as long as their public names differ — both names
then resolve to that value, and the one used when writing is whichever comes first in
`Enum.GetNames` order, which is neither declaration order nor the arithmetic one.

## When to suppress

Never. There is no reading of this shape that produces a usable contract.
