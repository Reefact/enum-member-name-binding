# EMN0004 — A public name contains a comma

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0004.fr.md)

| | |
|---|---|
| **Severity** | Error |
| **Category** | ApiContract |
| **Also enforced** | at start-up, by `EnumContractException` |

## Cause

A member declares a public name containing a comma.

<!-- emn:allow=EMN0004 -->
```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read,write")] ReadWrite = 3   // EMN0004
}
```

## Why it matters

A comma separates the values of a combination — `read, write` means both. A name that itself
contains a comma cannot be told apart from a combination of two members, so the value can be written
but never read back.

`System.Text.Json` rejects the same shape at first use, for the same reason.

The rule applies to **every** enum, not only to a `[Flags]` one. It used to stop at `[Flags]`, on
the reading that a comma only separates values there — but neither `Enum.Parse` nor
`System.Text.Json` looks at the attribute before splitting, so `"a,b"` is unreadable on an ordinary
enum too.

## How to fix

Choose a name without a comma.

```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read")]       Read      = 1,
    [JsonStringEnumMemberName("write")]      Write     = 2,
    [JsonStringEnumMemberName("read_write")] ReadWrite = 3
}
```

## When to suppress

Never.
