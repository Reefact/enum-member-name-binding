# EMN0004 — A public name on a `[Flags]` enum contains a comma

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0004.fr.md)

| | |
|---|---|
| **Severity** | Error |
| **Category** | ApiContract |
| **Also enforced** | at start-up, by `EnumContractException` |

## Cause

A member of a `[Flags]` enum declares a public name containing a comma.

<!-- emn:allow=EMN0004 -->
```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read,write")] ReadWrite = 3   // EMN0004
}
```

## Why it matters

`System.Text.Json` refuses the shape outright: building a converter for the enum above throws
`InvalidOperationException`, and the message says why in as many words — *"Flags enums must
**additionally** not contain commas"*. So the enum cannot be serialized at all, and this rule turns
that run-time failure into a build error.

## Only on a `[Flags]` enum

This rule reported every enum for a while, on the reading that a comma separates values everywhere
so a name carrying one can never be read back. The first half is true; the second does not follow.
The serializer looks the trimmed value up **as one name before it splits anything**, so on an
ordinary enum a declared `news,world` both writes and reads back:

```csharp
public enum Topic
{
    [JsonStringEnumMemberName("news,world")] NewsWorld = 4,
    [JsonStringEnumMemberName("news")]       News      = 1,
    [JsonStringEnumMemberName("world")]      World     = 2
}
```

`?value=news,world` binds `NewsWorld`, not `News | World` — the name wins, because it is looked up
first. `?value=news, world` is the combination, because no name is spelled with that space; it is
`1 | 2`, which names no member, and is refused like any other such combination
([limitations](../limitations.en.md#a-combination-naming-no-member-is-refused-outside-the-body)).

Reporting that enum refused a contract the serializer accepts, which is the one thing this package
is not allowed to do. The rule now stops where the serializer stops.

## How to fix

Choose a name without a comma.

```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read")]       Read      = 1,
    [JsonStringEnumMemberName("write")]      Write     = 2,
    [JsonStringEnumMemberName("read_write")] ReadWrite = 3
}
```

## When to suppress

Never. The enum cannot be serialized by `System.Text.Json` at all, so suppressing the rule only moves
the failure to the first request.
