# EMN0005 — Un nom public masque le nom C# d'un autre membre

🌍 **Langues :**  
🇬🇧 [English](./EMN0005.en.md) | 🇫🇷 Français (ce fichier)

| | |
|---|---|
| **Sévérité** | Erreur |
| **Catégorie** | ApiContract |
| **Également appliqué** | au démarrage, par `EnumContractException`, y compris lorsque `AllowPartialContracts` est activé |

## Cause

Un membre déclare un nom public qui est aussi le nom C# d'un autre membre, non annoté. La comparaison
ignore la casse.

<!-- emn:allow=EMN0003,EMN0005 -->
```csharp
public enum Colour
{
    [JsonStringEnumMemberName("Blue")] Red,   // EMN0005
    Blue
}
```

## Pourquoi c'est important

Deux recherches ont lieu, dans cet ordre :

1. les noms publics déclarés, comparés **en respectant la casse** ;
2. les noms C# des membres non annotés, comparés **sans tenir compte de la casse**.

L'énumération ci-dessus se comporte donc ainsi :

```
?colour=Blue   → Red      le nom déclaré est comparé en premier
?colour=blue   → Blue     pas de correspondance exacte, le nom C# est utilisé
?colour=BLUE   → Blue
```

`Blue` répond à toutes les casses de son nom **sauf la sienne**. Aucun lecteur de cette énumération ne
le devinerait, et aucun appelant de cette API ne pourrait le découvrir depuis le document OpenAPI non
plus.

La casse du nom déclaré n'y change rien, et c'est pourquoi la règle ignore la casse :
`[JsonStringEnumMemberName("blue")] Red` à côté de `Blue` produit l'image miroir du même piège —
`blue` résout vers `Red`, tandis que `Blue` et `BLUE` résolvent vers `Blue`.

## Comment corriger

Soit choisir un nom public qui n'entre en collision avec rien :

<!-- emn:allow=EMN0003 -->
```csharp
public enum Colour
{
    [JsonStringEnumMemberName("crimson")] Red,
    Blue
}
```

soit annoter l'autre membre également, ce qui le retire entièrement de la recherche par nom C# :

```csharp
public enum Colour
{
    [JsonStringEnumMemberName("Blue")]  Red,
    [JsonStringEnumMemberName("azure")] Blue
}
```

La seconde forme est légale mais déroutante, et annoter chaque membre est de toute façon ce que
demande [EMN0003](EMN0003.fr.md).

## Quand la supprimer

Jamais. Cette règle ne se déclenche qu'aux côtés d'EMN0003, puisqu'elle a besoin d'un membre non
annoté — et c'est précisément la règle qui vous protège encore une fois EMN0003 désactivée pour
autoriser les contrats partiels.
