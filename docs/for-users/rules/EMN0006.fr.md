# EMN0006 — Le nom public ne peut pas voyager sur tous les canaux d'entrée

🌍 **Langues :**  
🇬🇧 [English](./EMN0006.en.md) | 🇫🇷 Français (ce fichier)

| | |
|---|---|
| **Sévérité** | Avertissement |
| **Catégorie** | ApiContract |
| **Également appliqué** | non — celle-ci est uniquement à la compilation |

## Cause

Une valeur de `[JsonStringEnumMemberName]` contient un caractère qu'au moins un canal d'entrée refuse.

<!-- emn:allow=EMN0006 -->
```csharp
public enum Section
{
    [JsonStringEnumMemberName("news/world")] World,     // EMN0006 — une barre oblique
    [JsonStringEnumMemberName("épuisé")]     SoldOut    // EMN0006 — hors ASCII imprimable
}
```

## Pourquoi c'est important

Cette bibliothèque promet un seul contrat sur tous les canaux d'entrée. Cette promesse ne tient que
pour les noms que chaque canal peut réellement transporter, et trois familles ne le peuvent pas. Le
tableau ci-dessous a été produit en envoyant chaque caractère sur les cinq canaux face à un serveur en
fonctionnement, il n'a pas été lu dans une spécification :

| Dans un nom | route | requête | en-tête | formulaire | corps |
|---|:---:|:---:|:---:|:---:|:---:|
| `/` | **400** | ✅ | ✅ | ✅ | ✅ |
| CR, LF | ✅ | ✅ | **400** | ✅ | ✅ |
| hors ASCII imprimable (`é`, ` `, ` `) | ✅ | ✅ | **refusé par le client** | ✅ | ✅ |
| `?` `#` `&` `=` `+` `%` espace tabulation `\` `"` | ✅ | ✅ | ✅ | ✅ | ✅ |

Une barre oblique encodée est refusée dans un segment de route par ASP.NET Core. Une valeur d'en-tête
ne peut pas contenir de saut de ligne, et en pratique ne peut pas contenir de non-ASCII non plus —
`HttpClient` refuse de l'envoyer, si bien que la requête n'atteint jamais le serveur.

Les autres caractères de contrôle ont voyagé intacts lors de cette mesure, mais la RFC 9110 les
interdit dans une valeur de champ : ils sont donc signalés eux aussi. Cette partie de la règle repose
sur la norme plutôt que sur l'observation, et c'est dit ici plutôt que fondu dans le reste.

La tabulation est le seul caractère de contrôle épargné, parce que cette même norme l'admet. La
RFC 9110 écrit une valeur de champ `field-content = field-vchar [ 1*( SP / HTAB / field-vchar )
field-vchar ]` — une tabulation y est licite exactement là où une espace l'est, et le tableau ci-dessus
dit que les deux voyagent. Cette grammaire n'en admet qu'entre deux caractères visibles, et un nom qui
commence ou se termine par une espace blanche est déjà rejeté par [EMN0002](EMN0002.fr.md).

## Pourquoi un avertissement, et pas une erreur

Contrairement à [EMN0001](EMN0001.fr.md) à [EMN0005](EMN0005.fr.md), il ne s'agit pas d'une ambiguïté
— le contrat est parfaitement défini. C'est une limite de portabilité, et savoir si elle mord dépend
des canaux depuis lesquels votre API lie réellement. Un nom refusé seulement dans un en-tête ne coûte
rien à une API qui n'en lie jamais, et un nom public français comme `épuisé` est un choix de
conception légitime pour une API qui n'utilise que des routes, des chaînes de requête et des corps.

Le message nomme le caractère fautif et le canal qui le refuse, afin que la décision puisse se prendre
nom par nom.

## Comment corriger

Choisissez un nom dans l'ASCII imprimable, sans barre oblique :

```csharp
public enum Section
{
    [JsonStringEnumMemberName("news_world")] World,
    [JsonStringEnumMemberName("sold_out")]   SoldOut
}
```

## Quand la supprimer

Quand l'énumération n'est jamais liée depuis le canal qui refuse le nom. Supprimez-la sur le membre,
afin que la décision reste visible à côté du nom qu'elle concerne :

```csharp
[SuppressMessage("ApiContract", "EMN0006", Justification = "Lié depuis le corps et la requête uniquement.")]
[JsonStringEnumMemberName("épuisé")]
SoldOut
```

Ou désactivez la règle en bloc, si aucune énumération de la solution n'est jamais liée depuis un
en-tête ou une route :

```ini
[*.cs]
dotnet_diagnostic.EMN0006.severity = none
```
