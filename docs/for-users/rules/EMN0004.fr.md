# EMN0004 — Un nom public contient une virgule

🌍 **Langues :**  
🇬🇧 [English](./EMN0004.en.md) | 🇫🇷 Français (ce fichier)

| | |
|---|---|
| **Sévérité** | Erreur |
| **Catégorie** | ApiContract |
| **Également appliqué** | au démarrage, par `EnumContractException` |

## Cause

Un membre déclare un nom public contenant une virgule.

<!-- emn:allow=EMN0004 -->
```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read,write")] ReadWrite = 3   // EMN0004
}
```

## Pourquoi c'est important

Une virgule sépare les valeurs d'une combinaison — `read, write` signifie les deux. Un nom qui
contient lui-même une virgule ne peut pas être distingué d'une combinaison de deux membres : la
valeur peut être écrite, mais jamais relue.

`System.Text.Json` rejette la même forme à la première utilisation, pour la même raison.

La règle s'applique à **toutes** les énumérations, pas seulement aux `[Flags]`. Elle s'arrêtait
autrefois à `[Flags]`, sur l'idée qu'une virgule n'y sépare des valeurs que là — mais ni
`Enum.Parse` ni `System.Text.Json` ne regardent l'attribut avant de découper, donc `"a,b"` est
illisible sur une énumération ordinaire aussi.

## Comment corriger

Choisissez un nom sans virgule.

```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read")]       Read      = 1,
    [JsonStringEnumMemberName("write")]      Write     = 2,
    [JsonStringEnumMemberName("read_write")] ReadWrite = 3
}
```

## Quand la supprimer

Jamais.
