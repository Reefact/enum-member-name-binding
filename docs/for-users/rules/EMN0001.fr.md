# EMN0001 — Deux membres d'énumération déclarent le même nom public

🌍 **Langues :**  
🇬🇧 [English](./EMN0001.en.md) | 🇫🇷 Français (ce fichier)

| | |
|---|---|
| **Sévérité** | Erreur |
| **Catégorie** | ApiContract |
| **Également appliqué** | au démarrage, par `EnumContractException` |

## Cause

Deux membres de la même énumération déclarent la même valeur dans `[JsonStringEnumMemberName]`.

<!-- emn:allow=EMN0001 -->
```csharp
public enum Status
{
    [JsonStringEnumMemberName("same")] First,   // EMN0001
    [JsonStringEnumMemberName("same")] Second
}
```

## Pourquoi c'est important

Un nom public est la façon dont un appelant désigne un membre de votre énumération. Quand deux
membres répondent au même nom, la valeur n'est pas résoluble, et ce paquet refuse l'énumération
purement et simplement plutôt que de choisir à votre place : `EnumContractException` au démarrage, et
cette règle à la compilation.

Ce refus est toute la raison d'être de la règle, car l'alternative est ce que fait
`System.Text.Json` de cette forme — voir ci-dessous.

`System.Text.Json` rejette la même forme.

## Comment corriger

Donnez à chaque membre un nom public distinct.

```csharp
public enum Status
{
    [JsonStringEnumMemberName("first")]  First,
    [JsonStringEnumMemberName("second")] Second
}
```

Deux membres peuvent partager la même valeur *numérique* tant que leurs noms publics diffèrent : les
deux noms résolvent alors vers cette valeur, et celui utilisé en écriture est le premier dans
l'ordre d'`Enum.GetNames`, qui n'est ni l'ordre de déclaration ni l'ordre arithmétique.

## Quand la supprimer

Jamais. Aucune lecture de cette forme ne produit un contrat utilisable.
