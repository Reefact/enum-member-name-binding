# EMN0006 — The public name cannot travel on every input channel

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0006.fr.md)

| | |
|---|---|
| **Severity** | Warning |
| **Category** | ApiContract |
| **Also enforced** | no — this one is compile-time only |

## Cause

A `[JsonStringEnumMemberName]` value contains a character that at least one input channel refuses.

```csharp
public enum Section
{
    [JsonStringEnumMemberName("news/world")] World,     // EMN0006 — a slash
    [JsonStringEnumMemberName("épuisé")]     SoldOut    // EMN0006 — outside printable ASCII
}
```

## Why it matters

This library promises one contract on every input channel. That promise only holds for names every
channel can actually carry, and three families cannot. The table below was produced by sending each
character over all five channels against a running server, not read off a specification:

| In a name | route | query | header | form | body |
|---|:---:|:---:|:---:|:---:|:---:|
| `/` | **400** | ✅ | ✅ | ✅ | ✅ |
| CR, LF | ✅ | ✅ | **400** | ✅ | ✅ |
| outside printable ASCII (`é`, ` `, ` `) | ✅ | ✅ | **refused by the client** | ✅ | ✅ |
| `?` `#` `&` `=` `+` `%` space tab `\` `"` | ✅ | ✅ | ✅ | ✅ | ✅ |

An encoded slash is refused inside a route segment by ASP.NET Core. A header value cannot contain a
line break, and in practice cannot contain non-ASCII either — `HttpClient` refuses to send it, so the
request never reaches the server.

Other control characters travelled intact in that measurement, but RFC 9110 forbids them in a field
value, so they are reported too. That part of the rule rests on the standard rather than on the
observation, and is called out here rather than blurred into it.

## Why a warning, and not an error

Unlike [EMN0001](EMN0001.en.md) to [EMN0005](EMN0005.en.md), this is not an ambiguity — the contract is
perfectly well defined. It is a portability limit, and whether it bites depends on the channels your
API actually binds from. A name refused only in a header costs nothing in an API that never binds
one, and a French public name like `épuisé` is a legitimate design choice for an API that only uses
routes, query strings and bodies.

The message names the offending character and the channel that refuses it, so the decision can be
made per name.

## How to fix

Choose a name inside printable ASCII, without a slash:

```csharp
public enum Section
{
    [JsonStringEnumMemberName("news_world")] World,
    [JsonStringEnumMemberName("sold_out")]   SoldOut
}
```

## When to suppress

When the enum is never bound from the channel that refuses the name. Suppress it on the member, so
the decision stays visible next to the name it concerns:

```csharp
[SuppressMessage("ApiContract", "EMN0006", Justification = "Bound from the body and query only.")]
[JsonStringEnumMemberName("épuisé")]
SoldOut
```

Or turn the rule off wholesale, if no enum in the solution is ever bound from a header or a route:

```ini
[*.cs]
dotnet_diagnostic.EMN0006.severity = none
```
