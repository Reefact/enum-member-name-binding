# EMN0003 — The enum contract is incomplete

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0003.fr.md)

| | |
|---|---|
| **Severity** | Error |
| **Category** | ApiContract |
| **Also enforced** | at start-up, by `EnumContractException`, unless `AllowPartialContracts` is set |

## Cause

An enum declares a contract — at least one member carries `[JsonStringEnumMemberName]` — but some
members do not.

<!-- emn:allow=EMN0003 -->
```csharp
public enum Shipping
{
    [JsonStringEnumMemberName("express")] Express,
    Standard                                        // EMN0003
}
```

## Why it matters

The attribute **replaces** a member's name; it does not add an alias. A member left unannotated
therefore answers to its C# name, and that C# name becomes part of your public API contract:

```
GET /orders?mode=Standard   → 200
GET /orders?mode=standard   → 200
```

Renaming `Standard` in your code is then a breaking change for every caller — which is precisely
what declaring an explicit contract was meant to prevent. Forgetting one member is a mistake, not a
design choice, so it is reported as an error.

## How to fix

Annotate every member.

```csharp
public enum Shipping
{
    [JsonStringEnumMemberName("express")]  Express,
    [JsonStringEnumMemberName("standard")] Standard
}
```

## When to suppress

When the enum is not yours to annotate — one coming from a dependency, for instance. Opt in
explicitly at registration:

<!-- emn:skip -->
```csharp
.AddEnumMemberNameBinding(options => options.AllowPartialContracts = true);
```

and turn the rule off, since the analyzer cannot see your runtime configuration:

```ini
[*.cs]
dotnet_diagnostic.EMN0003.severity = none
```

Keep [EMN0005](EMN0005.en.md) on. Once EMN0003 is off, it is the only rule left protecting you from a
declared name shadowing an unannotated member.
