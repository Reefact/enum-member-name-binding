# EMN0004 — A `[Flags]` public name contains a comma

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0004.fr.md)

| | |
|---|---|
| **Severity** | Error |
| **Category** | ApiContract |
| **Also enforced** | at start-up, by `EnumContractException` |

## Cause

A member of a `[Flags]` enum declares a public name containing a comma.

```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read,write")] ReadWrite = 3   // EMN0004
}
```

## Why it matters

A `[Flags]` value is expressed as a comma-separated list — `read, write` means both. A name that
itself contains a comma cannot be told apart from a combination of two members, so the value can be
written but never read back.

`System.Text.Json` rejects the same shape at first use, for the same reason.

The rule does **not** apply to an enum without `[Flags]`, where a comma is just an ordinary
character and no splitting takes place.

## How to fix

Choose a name without a comma.

```csharp
[Flags]
public enum Scopes
{
    [JsonStringEnumMemberName("read")]       Read      = 1,
    [JsonStringEnumMemberName("write")]      Write     = 2,
    [JsonStringEnumMemberName("read_write")] ReadWrite = 3
}
```

## When to suppress

Never.
