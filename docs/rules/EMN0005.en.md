# EMN0005 — A public name shadows the C# name of another member

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./EMN0005.fr.md)

| | |
|---|---|
| **Severity** | Error |
| **Category** | ApiContract |
| **Also enforced** | at start-up, by `EnumContractException`, including when `AllowPartialContracts` is set |

## Cause

A member declares a public name that is also the C# name of another, unannotated member. The
comparison ignores case.

<!-- emn:allow=EMN0003,EMN0005 -->
```csharp
public enum Colour
{
    [JsonStringEnumMemberName("Blue")] Red,   // EMN0005
    Blue
}
```

## Why it matters

Two lookups happen, in this order:

1. the declared public names, compared **case-sensitively**;
2. the C# names of unannotated members, compared **case-insensitively**.

So the enum above behaves like this:

```
?colour=Blue   → Red      the declared name is matched first
?colour=blue   → Blue     no exact match, so the C# name is used
?colour=BLUE   → Blue
```

`Blue` answers to every casing of its name **except its own**. No reader of that enum would guess it,
and no caller of that API could discover it from the OpenAPI document either.

The casing of the declared name does not change anything, which is why the rule ignores case:
`[JsonStringEnumMemberName("blue")] Red` next to `Blue` produces the mirror image of the same trap —
`blue` resolves to `Red`, while `Blue` and `BLUE` resolve to `Blue`.

## How to fix

Either choose a public name that collides with nothing:

<!-- emn:allow=EMN0003 -->
```csharp
public enum Colour
{
    [JsonStringEnumMemberName("crimson")] Red,
    Blue
}
```

or annotate the other member too, which removes it from the C# name lookup entirely:

```csharp
public enum Colour
{
    [JsonStringEnumMemberName("Blue")]  Red,
    [JsonStringEnumMemberName("azure")] Blue
}
```

The second form is legal but confusing, and annotating every member is what
[EMN0003](EMN0003.en.md) asks for anyway.

## When to suppress

Never. This rule only fires alongside EMN0003, since it needs an unannotated member — and it is
specifically the rule that still protects you once EMN0003 has been turned off to allow partial
contracts.
